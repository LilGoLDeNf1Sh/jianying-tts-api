# 剪映配音 HTTP 接口设计

**目标**：复用用户已登录剪映客户端的官方后台能力，动态同步当前账号可用音色，并将文本合成为 MP3。

**架构**：FastAPI 仅绑定 127.0.0.1。请求进入后，服务端从客户端发布的本地发现文件取得短期桥接信息（只在内存使用），建立隔离会话，调用客户端 JSB。音色通过分类与分页自动去重同步；合成由客户端完成公共参数和请求签名，服务端只接收任务结果并验证、下载 HTTPS MP3。不读取或导出 Cookie，不修改客户端文件，不绕过会员权限。

**接口**：
- `GET /health`：进程状态。
- `GET /voices?query=...&refresh=true`：同步/搜索音色；默认使用成功缓存，`refresh` 强制同步。
- `POST /tts`：`{text, voice}`；`voice` 支持唯一名称、speakerId 或 resourceId。直接返回 `audio/mpeg`，保存一份在 `output/`。
- `GET /audio/{uuid}`：仅下载本次服务生成的 UUID 文件，防止路径穿越。

**约束**：文本 1–100000 字（后续版本移除了120字上限），单次最长 90 秒，MP3 最大 25 MiB；不记录文本、令牌或签名 URL；上游错误转换为用户可读错误。测试覆盖分页去重、音色解析、会员检查、MP3 验证、HTTP 响应和路径安全。

**兼容性**：参考实现验证于剪映 11.5；本机 6.0.1 是否提供同一桥接与 SystemTTS 协议必须实测。若不兼容，保留独立 bridge 适配层，根据旧版已发布接口适配，不宣称已完成在线合成。
